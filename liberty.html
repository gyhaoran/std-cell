30.1 从外向内：别只截出 values 就开始解释

完整例子是EDU_INV 的教学 Liberty。它具备 library/cell/pin/timing/template 的完整嵌套，便于学习语法和表索引；但缺少发布库所需的输入电容、功耗、物理面积等信息，不应交给生产流程当成完整库。

library (EDU_TT) {                    /* 一组共同单位与条件 */
  time_unit : "1ns";
  capacitive_load_unit (1, pf);
  lu_table_template (delay_3x3) {      /* 每个轴是什么 */
    variable_1 : input_net_transition;
    variable_2 : total_output_net_capacitance;
    index_1 ("0.02, 0.08, 0.2");
    index_2 ("0.005, 0.02, 0.05");
  }
  cell (EDU_INV) {
    pin (A) { direction : input; }
    pin (Y) {
      direction : output;
      function : "!A";
      timing () {
        related_pin : "A";
        timing_sense : negative_unate;
        timing_type : combinational;
        cell_rise (delay_3x3) { /* values 见完整文件 */ }
        cell_fall (delay_3x3) { /* 输出下降对应的延迟 */ }
        rise_transition (delay_3x3) { /* 输出上升沿本身多宽 */ }
        fall_transition (delay_3x3) { /* 输出下降沿本身多宽 */ }
      }
    }
  }
}

上面为层次阅读摘录，含解释性空表，不能直接当完整模型使用；链接文件的四个表包含实际运行得到的全部数值。表中也可以局部给出 index_1/index_2 覆盖模板索引，阅读实际文件时应优先检查局部定义，再回到模板。

30.2 四张表：两张问“等多久”，两张问“边沿多慢”

表本例起点本例终点物理意义
cell_riseA 下降跨 50%Y 上升跨 50%对应输出上升的传播延迟
cell_fallA 上升跨 50%Y 下降跨 50%对应输出下降的传播延迟
rise_transitionY 上升跨 20%Y 上升跨 80%输出上升沿的转换时间
fall_transitionY 下降跨 80%Y 下降跨 20%输出下降沿的转换时间

rise/fall 命名这里都以输出 Y为准，不以输入 A 为准。INV 是 negative_unate，所以 A↑ 对应 Y↓；BUF 是 positive_unate，所以输入输出同向。MUX 选择或 XOR 输入的方向可能依赖其他状态，需要 non_unate 或条件弧描述。

延迟与 slew 都是时间，但不能互换。一个输出可能很晚才开始变、随后很快完成转换，表现为 delay 大但 slew 小；也可能很早开始缓慢变化，两个指标呈另一种组合。查表后的输出 slew 会影响后一级单元，因此它不是只给波形好不好看的附属数据。

30.3 index_1/index_2 是坐标，values 才是测量结果

本文模板的第一轴是输入转换时间，单位 ns；第二轴是输出负载，单位 pF。第一轴 0.08 表示 80 ps，第二轴 0.02 表示 20 fF。不同库甚至同一库的不同模板可能交换轴；librecell-lib 本地实现也存在负载作为第一轴的情况，所以不能背“index1 永远是 slew”。

cell_rise，单位 ns5 fF（0.005 pF）20 fF（0.02 pF）50 fF（0.05 pF）
20 ps（0.02 ns）0.011922940.025608230.05137137
80 ps（0.08 ns）0.022412800.047744820.07677878
200 ps（0.2 ns）0.033640570.072698610.11937260

三行对应第一轴三个索引，每行三列对应第二轴三个索引。第二行第二列就是上一章实测的 47.74482 ps。原始 SPICE 测量以秒输出，脚本乘 10⁹ 写成 ns；如果误把秒直接写进 time_unit:"1ns" 的库，数值会错九个数量级。

30.4 两轴都不在采样点上：亲手做一次双线性插值

查询输入 slew=50 ps、负载=12.5 fF，分别处于 20/80 ps 与 5/20 fF 的中点。取左上四格 d00、d01、d10、d11；先定义 u=(50-20)/(80-20)=0.5，v=(12.5-5)/(20-5)=0.5。

d = (1-u)(1-v)d00 + (1-u)v·d01 + u(1-v)d10 + uv·d11
  = (0.01192294 + 0.02560823 + 0.02241280 + 0.04774482) / 4
  = 0.0269221975 ns ≈ 26.9222 ps

这是从离散表推得的近似值，不是这个新条件下又跑了一次 SPICE。表征网格密度要用误差评估选择。对表范围外做外推时误差和工具策略更敏感；不能以“软件能给一个数”证明目标负载/转换时间可用。最大电容、最大转换时间等约束仍需独立检查。

30.5 时序单元的表不都是输出负载乘输入 slew

表征任务相关引脚/事件常见轴含义常见表名
组合传播A→Y输入转换时间、输出电容cell_rise/fall，rise/fall_transition
Clock-to-QCK 有效边沿→Q时钟转换时间、输出电容同样可以使用四张传播/转换表
Setup / holdD 相对 CK受约束引脚 D 与相关引脚 CK 的转换时间rise_constraint / fall_constraint
Recovery / removal异步控制释放相对 CK控制引脚与时钟的转换时间constraint 表，结合 timing_type 判断

例如 pin(D){ timing(){ related_pin:"CK"; timing_type:setup_rising; ... } } 中，setup_rising 的 rising 指相关 CK 的上升沿；组内 rise_constraint 则约束 D 上升事件。这两个 rise 的对象不同。对于 pin(Q) 下的 timing_type:falling_edge，falling 指相关时钟下降沿，组里的 cell_rise 仍是 Q 上升延迟。

30.6 功耗表的 rise/fall 也要先看所属 pin

在 pin(Q) → internal_power → rise_power 的层次下，rise 指 Q 上升，不能因 related_pin:"CKB" 就改说是 CKB 上升。related_pin 表示相关激励路径，related_pg_pin 表示相关供电网络；when 进一步限定适用状态。若功耗组属于输入 pin，则对应那个输入的转换。截图没有显示外层括号时，应该回到完整文件确认。

经典内部功耗表保存每次事件的能量模型，平均功率还要结合活动率等；与静态漏电组 leakage_power 不是一回事。此入门实验没有计算 internal_power，也没有把空项填零来伪造完整性。原始语义可核对 Synopsys Liberty 手册的 Internal Power Modeling。

30.7 从“可解析文件”到“可发布库”的检查清单

  1. 层次和语法：括号、表维度、索引数量、数值是否有限。
  2. 语义：function、状态定义、pin 方向、related_pin、时序方向与条件是否匹配电路。
  3. 单位与阈值：模型电压、温度、时间/电容单位、slew 阈值是否一致。
  4. 覆盖：所有支持单元、角点、弧、边沿、状态及负载范围是否完成；失败点是否保留根因。
  5. 物理一致：同名单元的 GDS、LEF、网表、提取和表征是否真是同一个版本。
  6. 下游验证：STA、综合与布局布线能否正确消费；不能只以 Liberty parser 不报错验收。
练习
  1. 本表第一行第三列是什么条件、什么单位？
  2. 负载在 5/20 fF 正中间，slew 正好 80 ps，应该取哪两个值？
  3. 为什么 1e31 不是通过扩大坐标轴就能使用的“超大有效延迟”？
答案

① 20 ps 输入、50 fF 负载下的输出上升延迟 0.05137137 ns。② 第二行前两列 0.02241280 与 0.04774482 ns，线性中点 0.03507881 ns。③ 它是可疑的无效/失败占位线索，必须回到日志与波形证明测量有效；不能靠插值修复不存在的事件。
