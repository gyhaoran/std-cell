第 15 章　新工艺迁移毕业项目

从 PDK 盘点到可重复生成，不用“换层号就算移植”

本章目标
  • 建立可追踪的 PDK 资料清点、能力矩阵和单元架构规格。
  • 按器件测试结构→INV→NAND/NOR→复杂门的顺序逐级打通。
  • 交付代码、技术文件、测试、外部验证和已知限制，而不只是若干 GDS。

15.1 先定义“迁移完成”

本教程的毕业目标不是“LibreCell 对新工艺跑完一次”，而是：

在固定 PDK、验证规则文件（deck）、工具、LibreCell 提交和环境下，可重复地从受控晶体管网表生成目标单元；所有层/器件/网络/单位可追踪；通过外部 DRC/LVS/ERC/PEX、边界拼接和 P&R 冒烟测试；输出视图一致；未支持能力有明确阻断或风险说明。

如果 PDK 本身不允许自动生成、缺少授权验证规则文件或不能把验证结果保存到项目环境中，应停在能力评估阶段，不得把教学结果标记为可制造。

15.2 阶段 0：冻结输入与许可边界

对象必须记录
PDK工艺 option、release/version、安装摘要、可使用工具与许可限制
DRC/LVS/PEXdeck 名、版本、runset、tool/version、适用 option
器件模型模型库、PVT 条件文件、温度/电压、合法几何范围
LibreCellfork、commit、patch series、Python/lock/container digest
库规格cell list、drive/Vt、目标 PVT、site/height、命名和交付视图
不要把受限 PDK、厂商应用资料或 deck 提交到公开教程仓库。公开代码只保存接口、规则 ID、hash/版本与不含专有数值的测试框架；私有配置在受控环境中管理。

15.3 阶段 1：PDK 资料清点

  1. 层：制造层、purpose、GDS map、pin/label、派生层、器件 marker、boundary。
  2. 器件：NMOS/PMOS/Vt/电压类型、D/G/S/B、model 名、W/L/nf/m、tap/well。
  3. 互连：接触孔、局部互连层（LI）、金属/通孔栈、优选方向、合法堆叠、通孔阵列。
  4. 规则：基础几何、条件 spacing/EOL、density、antenna、latch-up、EM、DFM。
  5. 库接口：site、track、power rail、tapless/tapped、edge/abutment、允许方向。
  6. 工具：batch 命令、环境变量、输入输出格式、error taxonomy 和零违规标准。

给每项一个权威 source 与 rule ID。不要用“类似某开放工艺”填空。

15.4 阶段 2：建立能力矩阵

等级判定行动
A：技术文件可表达已有内部层/器件结构，只有尺寸、map、成本不同配置+schema test+外部签核
B：需要局部生成扩展需注入层/标记层/特殊模板，但不改变核心布线拓扑扩展晶体管/模板/输出模块并增加几何基准测试
C：需要核心架构扩展LI/M3+、多切割层、复杂器件、四端体连接、额外布线层设计新的内部层/器件 API，联动布线、LVS 和输出模块
D：当前不支持/阻断规则或器件无法可靠生成/验证停止该工艺/单元类别，记录 gap 与实现计划

矩阵至少覆盖：模型识别、内部层栈、器件提取、阱/衬底接触与体端、注入层/Vt、基本规则、条件规则、引脚/LEF、外部 DRC/LVS/PEX、特征化、特殊物理单元。

15.5 阶段 3：先定标准单元架构

架构文档必须给出并说明理由：

  • DBU、manufacturing grid、site width、cell height/track 数；
  • 栅节距、NMOS/PMOS 可用高度与尺寸调整/多指策略；
  • VDD/VSS layer/width/y、相邻 row 的共享方式；
  • signal pin layer、access direction、每 pin 最低 access 目标；
  • well/implant/tap 架构和最大 tap 距离；
  • left/right/top/bottom boundary ownership、R0/MX 等合法方向；
  • filler、tap、endcap、decap、antenna cell 的接口。

不要直接用 PDK 最小规则拼出最低高度。先对 INV/NAND/NOR 做手工或脚本化可行性研究，确认晶体管、接触孔、至少一条内部走线和引脚接入点能共存。

15.6 阶段 4：建立技术适配骨架

  1. 从 dummy_tech.py 复制结构到私有适配目录，立即删除/替换所有 dummy 数值。
  2. 先实现 DBU、输出映射和输出模块，生成仅含边界/测试矩形的分层冒烟测试 GDS。
  3. 增加技术配置结构检查器：字段存在、量纲、键覆盖、通孔层对、网格整除和输出映射。
  4. 用显式 model mapping 替代首字母启发式；未知模型 fail closed。
  5. 按能力矩阵扩展内部层、通孔连接图、器件绘制、提取和输出模块。
  6. 把每个 DRM rule ID 映射到：生成约束、外部 deck 检查或已知 unsupported。

15.7 阶段 5：由小到大的逐级打通

关卡输入必须证明
层测试结构每个绘图层/引脚层/标签层/切割层的小矩形GDS 映射、DBU、查看器和验证规则均识别正确
器件测试结构单 NMOS、单 PMOS、阱/衬底接触、接触孔/通孔链外部提取的器件类型、D/G/S/B 和 W/L 正确，基础 DRC 无违规
INV2T完整流水线、信号/电源引脚、LVS/PEX、首次 LEF/GDS 叠图检查
NAND2/NOR24T串并联、共享扩散区、内部网络、共同栅顺序
AOI/OAI6T+分支网络、无简单共同 Euler 顺序、布线压力
MUX/XOR/宽驱动复杂/多指模型假设、折叠、引脚可接入性、拥塞与寄生
顺序/物理单元DFF、filler、tap、endcap时序 arc、边界职责和 row 集成

每一关都要保存参考原理图、版图、外部 DRC/LVS/PEX 结果和预期失败测试。上一关未通过，不扩大单元用例集。

15.8 阶段 6：最小回归用例集

回归不能只跑“当前能成功的单元”。至少包含：

  • INVX1：单位、最小结构；
  • INV 大驱动：finger/并联与 min-area 压力；
  • NAND2/NOR2：串并联对偶；
  • AOI21/OAI21：分支与层次布局；
  • MUX2/XOR2：复杂内部网络；
  • 一个故意错误模型名：应在读取阶段失败；
  • 一个无合法布线端点的配置：应输出明确诊断；
  • 每个 special/edge cell 类别至少一个。

不要在批处理末尾用 grep 只显示成功项，也不要用 shell 逻辑吞掉退出码。生成清单必须明确标记 pass/fail/skipped 与原因。

15.9 阶段 7：边界和行级测试

自动生成相邻拼接测试版图：

left_cell × right_cell × legal_orientation_pair
逻辑/物理 cell 类别覆盖，而不是简单全量平方爆炸

检查 well/implant/active/metal/pin/boundary 在 cell edge 的 spacing、notch、max gap、continuity；再生成多 row 测试确认上下 VDD/VSS、MX 镜像、tap/endcap/filler 的组合。

15.10 迁移交付物

交付内容
版本清单PDK/deck/tool/LibreCell/env/hash
能力矩阵A/B/C/D、证据、owner、阻断项
架构规格DBU/site/height/grid/rail/pin/tap/boundary
代码与技术文件最小 patch、schema、注释中的 rule ID，不含无权发布内容
测试unit、coupon、cell corpus、negative、abutment、P&R
验证证据DRC/LVS/ERC/PEX、特征化、视图一致性、QA 报告
已知限制unsupported rule/device/cell、风险、禁止使用范围
独立修改的标准：你能根据一个新规则定位到消费模块、设计测试并判断配置/代码边界；不是能照着另一个 tech 文件替换数字。
迁移 gate review
  1. 所有 PDK 事实是否有版本与权威来源？
  2. 任何 unsupported 是否会 fail closed，而不是静默生成？
  3. device coupon 是否证明 body、模型和 W/L 提取正确？
  4. 回归是否包括复杂门、失败样例和 abutment？
  5. 是否能从 GDS/LEF/Liberty 任一 pin 追到同一逻辑与网络？
