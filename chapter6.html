第 6 章　一个库要交付哪些视图

把“生成版图”放回完整的标准单元库开发流程

本章目标
  • 知道每类库视图保存什么、由谁产生、由谁使用。
  • 理解 cell characterization 不是从 GDS 文件里直接读取一条延迟。
  • 建立跨视图一致性和库级 QA 的基本概念。

6.1 标准单元库开发的闭环

库架构与规格
  ├─ 逻辑功能、cell list、drive/Vt、轨道高度、PVT
  ▼
晶体管级电路设计与 sizing ── SPICE 仿真
  ▼
版图生成/手工优化 ── DRC ── LVS
  ▼
寄生提取 PEX ── characterization ── Liberty
  ▼
GDS / LEF / CDL / Verilog / Liberty 等视图打包
  ▼
一致性检查、abutment、P&R、STA、功耗和回归
  └────────────────── 发现问题后回到前级修改

这是迭代闭环。比如 pin access 很差时，可能需要改变单元内部布线甚至晶体管放置；时序不达标时，可能重新 sizing，导致版图宽度和寄生变化。

6.2 五类核心视图

视图主要内容关键检查
GDS/OASIS完整层几何、cell hierarchy、文本layer/datatype、DBU、边界、pin 标记、DRC/LVS/PEX
LEFmacro size、site、symmetry、pin port、OBS与 GDS 对齐；pin 可访问；方向/use 正确
SPICE/CDLMOS 和其他器件、D/G/S/B、模型、W/L/m/nf端口顺序、模型名、参数单位、与提取网表 LVS
Verilog功能、时序检查或 specify、power-aware 行为逻辑与 Liberty/SPICE 一致；X 传播策略
Libertypin 属性、function、timing arc、constraint、power、PVT查找表单调性/完整性、arc sense、单位、跨 corner 一致性

LEF 中最容易误解的部分

  • SIZE 与 GDS 单元边界必须一致，并符合 site/row 步进。
  • PIN 可有多个 PORT 和多个矩形；这些是路由器允许落 via/接线的目标形状。
  • OBS 告诉路由器哪些区域已被单元内部几何占用。漏写会让芯片级路由穿过不该穿的地方。
  • DIRECTION、USE 影响逻辑和电源处理，不能把所有 pin 都笼统写成 INOUT/SIGNAL。

Liberty 中不是只有 delay

组合单元的一个输出可能有多个 timing arc，例如 NAND2 的 A→Y 与 B→Y；每条 arc 还区分输入上升/下降、输出上升/下降，并在 input slew × output capacitance 网格上给出延迟和 transition。顺序单元还需 setup、hold、recovery、removal、minimum pulse width 等约束。

6.3 表征如何连接版图与时序模型

  1. 用 PDK 模型建立指定 process、voltage、temperature 的仿真条件。
  2. 从通过 LVS 的版图提取寄生 R/C，得到 extracted netlist。
  3. 对每个有效 timing arc 扫描输入 slew 和输出 load，测量 delay/transition。
  4. 测量 internal power、switching power 相关量和不同输入状态下的 leakage。
  5. 生成 Liberty，并执行功能、单位、查找表、交叉 corner 和 STA 质量检查。

PVT 表示 process、voltage、temperature。一个库通常包含多个 corner；不同 corner 的模型和表不能混用。还可能有 statistical variation、LVF、CCS/ECSM 等更高级模型，入门项目可以先从 NLDM 开始，但必须知道工业交付不止一个典型角。

6.4 跨视图一致性是硬约束

必须一致的对象典型故障后果
cell nameGDS 是 NAND2X1，Liberty 是 NAND2_X1工具无法关联 macro 与时序单元
pin name/大小写LEF 用 ZN，Verilog 用 YP&R、仿真或 LVS 连接失败
pin direction/use输出写成 INPUT，VDD 写成 SIGNAL路由与电源意图错误
逻辑 function版图是 NAND，Liberty 声明 AND综合/STA 与硅片行为不一致
物理尺寸与单位LEF 高度和 GDS 边界差一个 DBU单元重叠、行对不齐或路由违规
端口顺序CDL subckt 与 LVS setup 顺序不一致假 LVS 失败或更危险的错误匹配

6.5 LibreCell 当前实际交付到哪里

本地 lclayout 的 dummy technology 配置了 GDS、LEF 和 Magic writer。它适合教学和研究原型，但当前 writer/验证的能力必须在交付前补齐：

  • LEF writer 当前把每个 pin 输出为 INOUT SIGNAL，pin direction/use 尚有 TODO；
  • LEF obstruction 为空，需根据内部布线和 PDK pin-access 策略生成或后处理；
  • 内部 LVS 只提取有限金属层并忽略 body，不能代替 PDK deck；
  • GDS/LEF 生成不包含完整 Liberty 表征，也不自动产生可签核的整套库包。
正确的项目定义：把 LibreCell 当成“可修改的单元版图生成核心”，再在外围连接 foundry DRC/LVS/PEX、表征、视图修补和库级回归。教程后半部分会明确每个接口。

6.6 最小教学库与生产库的差距

阶段建议单元验收重点
读图训练INV、NAND2、NOR2器件、拓扑、扩散共享
生成器 bring-up再加 AOI21/OAI21、XOR/MUX、不同宽度复杂拓扑、无共同 Euler、pin/routing 压力
库集成 smoke test加入 BUF、DFF、filler、tap、endcap时序 arc、物理单元、行拼接和 P&R
生产库按规格完整 cell/drive/Vt 集合全部 PVT、可靠性、DFM、硅相关与长期 QA
本章检查点
  1. 为什么 LEF 里需要 OBS，即使 GDS 中已经有内部金属？
  2. 为什么表征应基于通过 LVS 的 extracted netlist？
  3. 请列出至少五个跨视图必须一致的字段。
参考答案

芯片路由器通常只读 LEF 抽象，不会从 GDS 推断阻挡。使用 LVS 后的提取网表能证明被表征的寄生电路与参考原理图对应。cell/pin 名、pin 方向/use、逻辑 function、尺寸/单位、端口顺序、PVT 和电源命名等都需一致。

阅读依据：《CMOS集成电路后端设计与实战》第 3～9 章覆盖标准单元电路/版图、LEF、物理抽取和表征；工业库应用资料用于检查 cell 类别、表征与 QA 是否漏项，不复制其专有内容。
