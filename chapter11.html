第 11 章　单元内部布线

从三维路由图到 PathFinder 协商拥塞

本章目标
  • 理解 (layer, x, y) 节点、同层边和 via 边如何对应版图资源。
  • 说清 HVGraphRouter、PathFinderGraphRouter 与单 net router 的嵌套关系。
  • 准确区分 2003 年 PDF 的 gridless/river routing 与本地 LibreCell 的网格图路由。

11.1 从几何空间构造路由图

本地 routing_graph.create_routing_graph_base 在每个可路由层和每个网格点创建节点：

node = (layer, (x, y))

同层水平边：(M1,x,y) ── (M1,x+pitch_x,y)
同层垂直边：(M2,x,y) │  (M2,x,y+pitch_y)
跨层 via 边：(M1,x,y) ──via1── (M2,x,y)

routing_layers 中的 h/v 决定该层允许建立哪些方向的同层边。边权由水平/垂直单位权重乘长度得到；via 边使用 via_weights，并记录 via layer 和 multi_via。

11.2 不是所有网格边都合法

  1. 根据 min_spacing 构造层间 spacing graph。
  2. 检查候选 wire/via 边是否与已经存在的器件和几何冲突，删除非法边。
  3. 删除已被预布线图形占用的边。
  4. 从带 net 属性的 shapes 中提取 terminal 可接入节点。
  5. 把晶体管端子嵌入路由图，并为 pin/端子创建 virtual nodes。
  6. 反复删除非 terminal 的度 0/1 节点，确认剩余图连通。

如果某个网络没有合法 terminal，代码会提示使用 --debug-routing-graph。这通常不是“Dijkstra 坏了”，而是 grid offset、pitch、enclosure、spacing 或端子几何让图上没有可接入点。

11.3 实际 router 是三层包装

HVGraphRouter(
  PathFinderGraphRouter(
    DijkstraRouter()          # --signal-router dijkstra
    或 ApproxSteinerTreeRouter() # --signal-router steiner
  ),
  orientation_change_penalty=tech.orientation_change_penalty
)
层职责
单 net router给定当前成本，把该 net 的所有 terminals 连成一棵树
PathFinderGraphRouter多 net 反复 rip-up/reroute，更新当前占用成本和历史拥塞成本
HVGraphRouter把不同方向的边拆到虚拟节点，通过虚拟边对转弯收取 penalty，减少 zig-zag

11.4 Dijkstra 与近似 Steiner 选项

DijkstraRouter 的 spanning_subtree 从第一个 terminal 建树，每轮从当前树的所有节点出发，寻找通向尚未连接 terminal 的最低成本路径，再把路径加入树。源码注释称其基于 PathFinder 与 Prim 思想。

ApproxSteinerTreeRouter 把 node cost 和 edge cost 合并为图权重，再调用 NetworkX 的 Steiner tree approximation。它可能得到更好的多端共享拓扑，但通常更慢；CLI 帮助也把 dijkstra 标为快但不稳定、steiner 标为慢但结果更好。这是当前作者对实现的说明，不是对所有输入的数学保证。

11.5 PathFinder 如何协商拥塞

第一轮每个 net 都倾向于走便宜路径，可能互相抢同一资源。PathFinder 不立即永久锁死先到者，而是迭代提高冲突位置代价：

route all nets with current costs
        │
        ├─ no collision → finish
        │
        └─ collision → increase history cost at congested nodes
                       recompute net order / costs
                       rip up and reroute all nets

本地实现同时考虑：

  • base cost：层、长度、via 等固有成本；
  • present sharing cost：本轮已有多少 net 使用冲突资源；
  • history cost：某位置在过去迭代反复冲突的惩罚；
  • reserved nodes：某 net 的端子及其 spacing 邻域不能被其他 net 占用；
  • node conflict：即使不是同一个节点，距离过近的不同层/同层节点也不能同时用。

最多迭代 1000 次仍冲突就抛出 Failed to route。成功后还会逐 net 在避开其他已布网络的图上做一次优化。

11.6 从 routing tree 画回版图

每条同层边变为相应层的线段，跨层边变为 via/cut 和必要 enclosure。绘制完成后同层多边形合并。随后流水线才进入 notch/min-area 后处理、内部 LVS 和 writer；这些不是一个独立的“river detailed router”。

11.7 2003 PDF 与 LibreCell 不能混讲

维度std-cell-generator.pdf本地 LibreCell
年代与工具2003 年的独立参数化生成器本地提交 f708e3a 的 Python 项目
路由模型gridless、modified unreserved layer model由 pitch/offset 建立的 grid routing graph
全局路由整数规划/启发式、Prim、Lagrange 等PathFinder 协商拥塞 + Dijkstra/近似 Steiner 单 net tree
详细路由单独的 river routing 阶段直接把图上的层/坐标路径画成几何，没有 river router 类
可借鉴之处问题分解、成本和历史视角必须按源码、技术接口和当前限制学习

LibreCell 日志中有“Start global routing”，这是类内部对多 net 图路由的称呼；不要因此推断它随后一定还有传统芯片级 detailed routing。

11.8 调试 routing failure 的顺序

  1. 先用 --debug-routing-graph 输出路由图，检查 terminal 是否落在图上。
  2. 核对 grid pitch/offset、cell width/height、transistor offset。
  3. 核对 wire/via width、enclosure 和 spacing 是否把大量边删掉。
  4. 检查 routing layer 的 h/v、via connectivity 和 weight 字典是否完整。
  5. 比较 dijkstra 与 steiner；如果只有某算法成功，保存 placement 和日志分析。
  6. 最后才调整 cost；成本不能创造本来不存在的合法路径。
纸上 PathFinder 实验

画一个 5×5 网格，让 net A 与 net B 的最短路都经过中心点。第一轮标出冲突，给中心点加 history cost，再分别画第二轮路径。思考：若网格上只有这一条通道，无论怎样加 cost 为什么都不会成功？

本章检查点
  1. 一个路由节点为什么必须包含 layer？
  2. PathFinder 的 history cost 与 present cost 有什么不同？
  3. 为什么不能称 LibreCell 使用 PDF 中的 river routing？
参考答案

同一坐标在不同层是不同导体，只能通过 via 边连接。present cost 反映当前迭代共享，history cost 记忆过去反复拥塞。当前源码中没有 river router，图路径已经落到具体层和坐标并直接绘制。
