第 14 章　沿源码走完整流水线

知道每个中间状态在哪里，才有能力修改而不靠猜

本章目标
  • 从 CLI 入口追到网表、布局、几何生成、布线、后处理、LVS 和输出模块。
  • 理解每一步的输入/输出、不变量与失败模式。
  • 建立“改代码→单元测试→小单元→整库→外部签核”的修改纪律。

14.1 入口：standalone.main

  1. argparse 解析真实 CLI，按 -v/-q/--log 配置日志。
  2. load_tech_file 执行 Python 技术文件。
  3. 由字典把 --placer 和 --signal-router 变成布局器和布线器对象。
  4. 组合 HVGraphRouter(PathFinderGraphRouter(signal_router))。
  5. 构造 LcLayout 并调用 create_cell_layout。
  6. 运行内部 LVS；通过后遍历 output_writers 中的输出模块。

源码入口：librecell-layout/lclayout/standalone.py。第一次阅读不要从文件顶部逐行滚动，先找 main、create_cell_layout 和编号方法。

14.2 00–01：校验技术与读取网表

_00_00_check_tech 当前只做很少的检查，例如 multi_via 层对顺序；_00_01_prepare_tech 把间距字典变成无向图。

_01_load_netlist：

  • 通过 KLayout SPICE reader 查找 subckt；
  • 用模型名首字母判断 NMOS/PMOS；
  • 识别唯一 supply 与 ground，非电源端口作为 I/O pin；
  • 把 SPICE W 转为 DBU，乘全局 sizing factor，并夹到器件最小宽度。

这里是新工艺模型名、器件参数和 body 语义最早需要扩展的位置。建议把“模型名→ChannelType”从隐式字符串规则改为技术文件中的显式 mapping/callback，并为未知模型报错。

14.3 02–03：内部版图与抽象布局

_02_setup_layout 创建顶层单元，并按固定内部 layermap 为每个语义层建立图形容器。开启布线图调试时还会创建调试用途层。

_03_place_transistors 调用选定布局器，得到两行槽位单元。若传入布局文件路径：

  • 文件存在：校验单元、晶体管名、网络和位置后加载；
  • 文件不存在：运行布局器后保存 JSON。

这是保证 A/B 实验可比的接口，也意味着过期布局文件会绕过新布局器。

14.4 04–05：画晶体管和单元模板

DefaultTransistorLayout 用抽象槽位与技术参数生成：

  • NMOS/PMOS 对应的 diffusion；
  • gate Poly、well enclosure；
  • 带 net 属性的源/漏/栅图形；
  • 不在网格上的端子节点，供后续布线接入。

_05_draw_cell_template 计算单元宽度，绘制模板、VDD/VSS 电源轨和电源引脚图形。若新工艺需要注入层、阱/衬底接触、特殊栅切割或鳍数离散化，仅调整 GDS 映射无法解决，应在晶体管/模板抽象层增加显式生成逻辑。

14.5 06–08：构图、布线和绘制

_06_route 包含了构图和实际多网络布线：

  1. 创建 Grid2D 与基础 layer-coordinate graph；
  2. 删除与已有几何冲突或已预布的边；
  3. 提取/嵌入端子，创建虚拟端子/引脚；
  4. 建立 spacing conflict 与 reserved node 集合；
  5. 调用 HV、PathFinder 和信号布线器组成的层次结构。

_08_draw_routes 把布线树画成导线/通孔并合并同层多边形。没有另一个河流式布线方法。

14.6 09：有限的后处理

_09_post_process 的核心工作：

  • 对配置了 minimum_notch 的层填凹槽，连续做两次；
  • 只有 connectable_layers 可在全层区域上填充并潜在合并图形；其他层逐多边形处理以避免短接不同网络；
  • 调用 SMT-based cleaner 修复配置的 min_area；
  • 从虚拟引脚邻接的布线点注册引脚几何，并绘制引脚/标签。
它不是完整 DRC 修复器。它不保证修复所有 width/space/EOL/density/antenna/implant/well 规则，也不能宣称会普遍“平滑扩散”或“自动扩 N-Well”。结果必须运行外部 deck。

14.7 内部 LVS 与输出模块

create_cell_layout 返回后，main 才读取参考网表、把四端 MOS 转为三端 MOS、从版图提取网表并比较。失败且未使用调试选项/--ignore-lvs 时退出，不写最终文件。

通过后依次调用输出模块：

  • GDS writer：重新映射内部层、设置 GDS DBU、写 CELL.gds；
  • LEF writer：由引脚几何生成宏单元，但当前方向/用途/OBS 有明显 TODO；
  • Magic writer：按自己的层名和缩放因子写 .mag。

14.9 一次安全的源码修改流程

  1. 写需求和不变量：例如“未知模型必须报错，原 nmos/pmos 行为不变”。
  2. 先写最小测试：一个正例、一个边界例、一个失败例。
  3. 只改最小接口：避免同时改层、单位和算法。
  4. 跑 INV/NAND/NOR：检查布局、布线、内部 LVS、GDS/LEF。
  5. 跑压力 corpus：AOI/OAI、MUX/XOR、宽器件、无共同 Euler。
  6. 跑外部 PDK 闭环：DRC/LVS/PEX、相邻拼接、P&R、特征化。
  7. 记录差异：输出哈希、面积、导线/通孔、违规分类、时序/功耗。

毕业前的最小源码练习

把“模型名首字母判断”重构成技术文件显式 mapping 的设计方案：定义 API、未知模型错误、向后兼容策略和测试，不必立刻编码。若方案没有覆盖外部 LVS，仍不完整。

本章检查点
  1. 内部 LVS 在输出模块之前还是之后？
  2. 增加 M3 为什么至少会影响五个模块？
  3. 凹槽填补为什么只允许部分层跨图形合并？
参考答案

LVS 在输出模块之前。M3 影响内部层/通孔连接图、布线、几何绘制、提取和输出。不同网络的金属图形若被全局填凹槽合并会短路，只有 nwell 等明确列入 connectable_layers 的层才允许这样处理。
