23.1 从几何空间构造布线图

本地 routing_graph.create_routing_graph_base 在每个可用于布线的层和每个网格点创建节点：

node = (layer, (x, y))

同层水平边：(M1,x,y) ── (M1,x+pitch_x,y)
同层垂直边：(M2,x,y) │  (M2,x,y+pitch_y)
跨层通孔边：(M1,x,y) ──via1── (M2,x,y)

routing_layers 中的 h/v 决定该层允许建立哪些方向的同层边。边权由水平/垂直单位权重乘长度得到；通孔边使用 via_weights，并记录通孔层和 multi_via。

23.2 不是所有网格边都合法

  1. 根据 min_spacing 构造层间间距关系图。
  2. 检查候选导线/通孔边是否与已经存在的器件和几何冲突，删除非法边。
  3. 删除已被预布线图形占用的边。
  4. 从带 net 属性的 shapes 中提取 terminal 可接入节点。
  5. 把晶体管端子嵌入布线图，并为引脚/端子创建虚拟节点。
  6. 反复删除非端子的度 0/1 节点，确认剩余图连通。

如果某个网络没有合法端子，代码会提示使用 --debug-routing-graph。这通常不是“Dijkstra 坏了”，而是网格节距/偏移、包围量、图形间距或端子几何让图上没有可接入点。

23.3 为什么明明画了很大的 PIN，却没有可接入点

先忘掉算法，只算几何。假设教学 M1 引脚为 x=100～200、y=100～200 nm 的正方形；通孔边长 40 nm，M1 四边包围至少 20 nm。孔中心到引脚任意边至少要留 40/2+20=40 nm，所以合法中心窗口收缩成 x/y=140～160 nm。

如果两方向候选中心都只取 100+100k nm，就没有点落入这个窗口。引脚确实存在、面积也不小，但布线资源图没有可用端子。若架构允许把轨道偏移改为 50 nm，则 (150,150) 成为候选；还必须检查 M2 包围、邻网及其他规则，不能只改轨道就宣告全局合法。

再看两条线：线宽各 60 nm、中心距 100 nm，边缘间距为 100−30−30=40 nm。若最小异网间距 50 nm，两条中心线虽然没有重合，仍不能同时布。这说明容量冲突不能只理解成“两个网踩同一个点”。

练习：保持孔和包围不变，把引脚缩为 70×70 nm，会怎样？

所需最小引脚宽为 40+2×20=80 nm；70 nm 连连续空间中的合法中心都没有，因此更密轨道也救不了。应先修改端口/通孔方案并重新验证几何。

23.4 实际布线器由三层封装组成

HVGraphRouter(
  PathFinderGraphRouter(
    DijkstraRouter()          # --signal-router dijkstra
    或 ApproxSteinerTreeRouter() # --signal-router steiner
  ),
  orientation_change_penalty=tech.orientation_change_penalty
)
层职责
单网络布线器给定当前成本，把该网络的所有端点连成一棵树
PathFinderGraphRouter对多个网络反复拆线重布，更新当前占用成本和历史拥塞成本
HVGraphRouter把不同方向的边拆到虚拟节点，通过虚拟边对转弯增加惩罚，减少曲折走线

23.5 Dijkstra 与近似 Steiner 选项

DijkstraRouter 的 spanning_subtree 从第一个端点建树，每轮从当前树的所有节点出发，寻找通向尚未连接端点的最低成本路径，再把路径加入树。源码注释称其基于 PathFinder 与 Prim 思想。

沿用A/B/C 经 O 相连的例子：第一步树只有 A；连接 B 后，树包含 A、O、B。接 C 时不必再从 A 走一遍 AO，而可以直接从树上的 O 出发增加 OC。这样公共金属只算一次。“从树出发”正是多源最短路在这里的用途，不是三个输入信号合并成同一张网。

ApproxSteinerTreeRouter 把节点成本和边成本合并为图权重，再调用 NetworkX 的 Steiner 树近似算法。它可能得到更好的多端共享拓扑，但通常更慢；CLI 帮助也把 dijkstra 标为快但不稳定、steiner 标为慢但结果更好。这是当前作者对实现的说明，不是对所有输入的数学保证。

23.6 PathFinder 如何协商拥塞

第一轮每个网络都倾向于走低成本路径，可能互相争抢同一资源。PathFinder 不立即永久锁死先到者，而是迭代提高冲突位置代价：

按当前成本为所有网络布线
        │
        ├─ 无冲突 → 完成
        │
        └─ 有冲突 → 提高拥塞节点的历史成本
                    重新计算网络顺序和成本
                    拆除并重新布置所有走线

本地实现同时考虑：

  • 基础成本（base cost）：层、长度、通孔等固有成本；
  • 当前共享成本（present sharing cost）：本轮已有多少网络使用冲突资源；
  • 历史成本（history cost）：某位置在过去迭代反复冲突的惩罚；
  • 保留节点（reserved nodes）：某网络的端子及其间距邻域不能被其他网络占用；
  • 节点冲突（node conflict）：即使不是同一个节点，距离过近的不同层/同层节点也不能同时使用。

最多迭代 1000 次仍冲突就抛出 Failed to route。成功后还会逐网络在避开其他已布网络的图上做一次优化。

历史成本为什么单独保留？本轮拆掉旧走线以后，当前位置占用可能暂时变成 0；若把过去拥塞也忘掉，各网可能又一起抢回同一窄通道，反复震荡。历史项让过去总是拥挤的区域在新一轮仍偏贵，鼓励尝试其他拓扑。但若两网唯一通路都必须经过一个容量为 1 的瓶颈，再多轮惩罚也不能产生合法解，应回头改变布局、层资源或架构。

23.7 从布线树画回版图

每条同层边变为相应层的线段，跨层边变为通孔/切割层和必要的包围图形。绘制完成后同层多边形合并。随后流水线才进入凹槽/最小面积后处理、内部 LVS 和输出模块；这些不是一个独立的“河流式详细布线器”。

23.8 2003 PDF 与 LibreCell 不能混讲

维度std-cell-generator.pdf本地 LibreCell
年代与工具2003 年的独立参数化生成器本地提交 f708e3a 的 Python 项目
布线模型无网格、改进的非保留层模型由节距/偏移建立的网格布线图
全局布线整数规划/启发式、Prim、Lagrange 等PathFinder 协商拥塞 + Dijkstra/近似 Steiner 单网络树
详细布线单独的河流式布线阶段直接把图上的层/坐标路径画成几何，没有河流式布线器类
可借鉴之处问题分解、成本和历史视角必须按源码、技术接口和当前限制学习

LibreCell 日志中有“Start global routing”，这是类内部对多网络图布线的称呼；不要因此推断它随后一定还有传统芯片级详细布线阶段。

23.9 调试布线失败的顺序

  1. 先用 --debug-routing-graph 输出布线图，检查端子是否落在图上。
  2. 核对网格节距/偏移、单元宽度/高度、晶体管偏移。
  3. 核对导线/通孔宽度、包围量和间距是否导致大量边被删除。
  4. 检查布线层的 h/v 方向、通孔连通关系和权重字典是否完整。
  5. 比较 dijkstra 与 steiner；如果只有某算法成功，保存布局结果和日志进行分析。
  6. 最后才调整成本；成本不能创造本来不存在的合法路径。
