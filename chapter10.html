第 10 章　晶体管布局

经典 Euler 思想与本地 LibreCell 实现逐行对齐

本章目标
  • 说清晶体管布局的硬约束、质量目标与输出形式。
  • 理解本地 EulerPlacer、HierarchicalPlacer 和 MetaTransistorPlacer 实际做了什么。
  • 能识别“理论上可能的算法”和“当前代码已经实现的算法”之间的差别。

10.1 布局器的输入与输出

输入是一组带有器件类型、栅网络、两个扩散网络和尺寸的晶体管。输出不是最终纳米坐标，而是一个抽象的 2×N 槽位网格（slot grid）：

upper row: PMOS  [ MP? ][ MP? ][ gap ][ MP? ]
lower row: NMOS  [ MN? ][ MN? ][ gap ][ MN? ]
                    x=0    x=1    x=2    x=3

每只器件还能交换源/漏方向。后续几何阶段再用栅间距、单元高度、晶体管偏移和器件宽度等技术参数把抽象槽位转为图形。

10.2 硬约束和优化目标要分开

类型例子违反后的含义
硬约束NMOS/PMOS 分行、槽位不重叠、相邻扩散网络匹配版图物理或电气不合法
主要目标减少扩散间断（diffusion gap）与总宽度面积可能更大
次级目标上下栅对齐、估计线长、输入/输出顺序布线更难或线更长
当前未充分建模真实 DRC、引脚可接入性、寄生、时序、整库边界布局评分好仍可能无法生成好单元

10.3 Euler 布局的理论骨架

  1. 把 NMOS 与 PMOS 分开，各自建立“扩散网络为顶点、晶体管为边”的多重图。
  2. 找一条覆盖所有晶体管边的 Euler 迹（Euler trail）；必要时通过虚边或分段处理非 Euler 图。
  3. 把 Euler 迹的边顺序变成晶体管行，沿路径方向决定器件是否翻转。
  4. 从候选 NMOS/PMOS 行中寻找栅标签尽量对齐的组合。
  5. 用估计线长、I/O 位置等进一步排序。

经典文献的主要洞察是：Euler 迹把“连续使用每只晶体管一次”和“相邻边共享顶点网络”统一起来。它并不自动解决现代引脚可接入、复杂切割/多重图形化或寄生优化问题。

10.4 本地 EulerPlacer 真实流程

入口位于 lclayout/place/euler_placer.py。本地版本的流程是：

  1. 分出 NMOS 和 PMOS，调用 _transistors2graph 建图。
  2. _find_optimal_single_row_placements 为两行分别产生最优宽度候选，并考虑循环移位。
  3. 对 NMOS/PMOS 候选做笛卡尔积，组成所有行对。
  4. 先取 _num_gate_matches 最大者。
  5. 再取 wiring_length_bbox 最小者。
  6. 最后用 I/O ordering cost 过滤，仍并列时取第一个。

当前代码中的 output_nets 被设为空集合，并有待完善输出网络提取。因此不要把 I/O 顺序优化理解为成熟的工业引脚布局优化。

组合爆炸仍然存在。若 NMOS 候选数×PMOS 候选数超过 100000，代码只打印“HierarchicalPlacer 可能更合适”的提示；它不会在 EulerPlacer 内自动切换。

10.5 HierarchicalPlacer 如何分区

本地 partition.py 的实现很具体：

  1. 遍历 transistor graph 的每条边；
  2. 每次遇到 power net，就把该端点替换成一个独立临时节点；
  3. 在变换后的图上调用 NetworkX connected_components；
  4. 把临时 supply 名映射回原网络。

这样多个只通过 VDD/VSS 相连的逻辑分支会成为独立子图。每个子图内部仍找最优宽度的单行布局，再附加扩散间隔；随后把子图抽象成带宽度和非电源网络集合的 SubCell，枚举上下行子单元排列并用网络包围盒估计优化。

它不是 min-cut，也不是“从输出 DFS 分类 CMOS 门”。当前分区逻辑只是“拆开 supply 节点后取连通分量”。教程讨论更先进的图划分只能作为改进方向，不能写成现有实现。

10.6 MetaTransistorPlacer 并不试跑全部布局器

meta_placer.py 只在 EulerPlacer 与 HierarchicalPlacer 之间做启发式选择：

  1. 构造 NMOS/PMOS 的全偶度图候选；任一侧超过 20 个就选层次布局。
  2. 每个全偶度图最多枚举 200 条 Euler 回路。
  3. 以 num_tours_n × num_tours_p 估计复杂度。
  4. 小于 400000 选 Euler 布局，否则选层次布局。

这些阈值是源码中的经验值。类文档字符串也称其为“极其粗略的启发式”。它没有运行 random、SMT、hillclimb 等布局器并比较真实版图质量。

10.8 如何评价和改进一个布局器

不要只记录单元宽度。建议输出多目标指标：

  • 槽位数、扩散间断数、上下栅匹配数；
  • 估计半周长线长（HPWL）与实际布线线长/通孔数；
  • 布线是否成功、PathFinder 迭代数；
  • 外部 DRC 分类计数、合法引脚接入点数；
  • PEX 后的输入电容、延迟、转换时间和内部功耗；
  • 运行时间和结果可复现性。

改动启发式后，用一个覆盖 INV、NAND/NOR、AOI/OAI、MUX/XOR、宽器件和无共同 Euler 顺序的固定用例集做回归。否则一个门变好可能让另一类门不可布。

源码阅读实验
  1. 从 standalone.py 的 placers 字典找到 CLI 名称与类。
  2. 在 MetaTransistorPlacer.get_placer 中标出 20、200、400000 三个阈值。
  3. 在 EulerPlacer.place 中按顺序标出 gate match、wiring bbox、I/O cost。
  4. 说明如果要加入引脚可接入性的估计指标，应在哪个候选过滤阶段插入以及如何回归。

  2. HierarchicalPlacer 的分区是否是 min-cut？
  3. 为什么共同 Euler 顺序仍不能保证可布线？
参考答案

不会，只在 Euler 布局与层次布局中启发式选一个。分区只是拆开供电节点后求连通分量。共同 Euler 顺序只优化扩散连续和栅对齐，未建模有限轨道、障碍、通孔、间距冲突与引脚可接入性。
