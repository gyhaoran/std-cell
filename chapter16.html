第 16 章　签核、表征与 P&R 回归

把单元版图变成可被综合、STA 和芯片路由可靠使用的库

本章目标
  • 搭建外部 DRC/LVS/ERC/PEX 与 characterization 的质量门禁。
  • 验证 GDS、LEF、CDL、Verilog 和 Liberty 的一致性。
  • 用 abutment、pin access、P&R、STA 和可复现性回归完成库级验收。

16.1 七级质量门

  1. 结构检查：文件可解析、cell/pin/单位/层/尺寸符合 schema。
  2. 物理检查：foundry DRC、ERC、antenna、density/DFM 和边界拼接。
  3. 电路等价：foundry LVS，包含 body、Vt、W/L/finger 和端口。
  4. 寄生提取：通过 LVS 的版图运行 PEX，检查 R/C 网络与单位。
  5. 表征：按 PVT、slew/load、timing arc 生成时序/功耗模型。
  6. 视图一致性：GDS/LEF/CDL/Verilog/Liberty 的名字、功能、pin 和尺寸一致。
  7. 集成回归：综合→P&R→STA/功耗→DRC/LVS smoke，验证真实消费者。

任何一级失败都不能用后一级的 pass 抵消。例如 STA 能跑完不代表 LEF obstruction 正确，LVS match 也不代表表征 corner 正确。

waiver 必须包含 rule、位置、理由、owner、风险和 foundry/项目批准；“生成器总会报这个”不是 waiver 理由。

16.3 LVS：参数和 body 都属于等价性

生产级 LVS 比较不止 topology。为每个 cell 保存：

  • reference CDL/SPICE 与端口顺序；
  • 提取器件类型、Vt/电压 option；
  • D/G/S/B 网络；
  • W/L/nf/m、并联/串联归并策略和容差；
  • 短路、开路、unmatched device/net 计数均为零。

对 tapless 单元，仍需在 foundry LVS/ERC 流程中使用官方支持的 cell context 或 runset，不能简单删除 body 后宣布匹配。

16.4 PEX 与仿真基线

每个需要表征的 cell 采用经过 LVS 的 extracted netlist。先做三个 sanity check：

  1. 无寄生/原理图仿真与逻辑真值表一致；
  2. PEX 仿真在轻载典型角仍功能正确，内部节点无浮空；
  3. 输入电容、输出电容和关键电阻数量级与版图变化趋势一致。

当扩大器件 W 后，若 extracted input cap 反而显著下降，应先怀疑单位、提取层或网表关联，不要直接把结果写进 Liberty。

16.5 组合单元 characterization

  1. 枚举每个输出 pin 的 Boolean function 和所有 sensitizable input→output arc。
  2. 对每条 arc 固定 side inputs 到能传播变化的 non-controlling value。
  3. 在 input slew × output load 网格上仿真 rise/fall delay 与 output transition。
  4. 测 internal power（输入切换时 cell 内耗能）和不同输入状态 leakage。
  5. 对每个 PVT/corner 生成独立 Liberty，并检查单位与表格完整性。

以 NAND2 为例，A→Y 的变化只有在 B=1 时能传播；B→Y 同理需 A=1。错误的 side-input condition 会得到不存在或不完整的 timing arc。

16.6 顺序单元额外需要什么

DFF/latch 除 clock-to-Q 外还需要 setup、hold、recovery、removal、minimum pulse width、clock gating check 等。约束可能为负，并依赖 data/clock slew。还要验证：

  • 功能、异步 set/reset 优先级与非法状态；
  • scan enable、SI/SO 和测试模式；
  • 状态保持、metastability 相关建模边界；
  • Verilog specify、Liberty sequential function 与 transistor circuit 一致。

16.7 Liberty QA

类别检查例
语法/schema单位、template、索引维度、所有引用存在
功能function/three-state、related_pin、timing_sense、when 条件
完整性每个有效 arc、rise/fall、constraint/power table 均存在
数值NaN/负 transition/异常跳变、随 load/slew 的合理趋势
跨角corner 标签、voltage/temperature、模型/文件关联无混用
跨视图cell/pin/function 与 Verilog、CDL、LEF 一致

不要机械要求所有 delay table 单调；真实电路可能有复杂行为。自动 checker 标记异常后，应回到 waveform、bench 和 PEX 判断。

16.8 LEF 与 pin access QA

LibreCell 当前 LEF writer 的已知问题必须先修复或后处理：正确的 DIRECTION/USE、POWER/GROUND、obstruction、site/symmetry 和必要 property。然后做：

  1. 把 LEF macro overlay 到 GDS，核对 origin、SIZE、boundary 和每个 pin port。
  2. 在所有合法 orientation 下枚举上层路由器的 via/access point。
  3. 验证输入、输出、电源 pin 都有足够且规则合法的 access。
  4. 运行一个高利用率小设计的 detailed routing，统计 unrouted、DRC 和 detour。

pin shape 越大不一定越易访问，它可能增加 obstruction、阻塞邻近 pin 或违反 via enclosure/spacing。

16.9 Abutment QA

按 cell edge signature 聚类以减少组合，同时保留代表性极端：

  • 最窄/最宽逻辑单元；
  • 边缘有/无 diffusion、implant、pin、metal 的类型；
  • filler/tap/endcap 与普通单元；
  • R0/MX 和相邻 row 组合；
  • 窗口跨边界的 density/DFM 检查。

除 DRC 外还检查 VDD/VSS 连续、well/tap 意图、site 对齐和拼接后 pin access。

16.10 P&R 与 STA smoke test

构造一个小而有压力的 RTL：

  • 让综合实际使用 INV/NAND/NOR/AOI/OAI/MUX/DFF 及多个 drive；
  • 包含长组合链、高扇出、时钟、reset 和拥塞区域；
  • 分别跑低/中/高 utilization；
  • 插入 filler/tap/endcap/antenna 修复，完成 detailed route；
  • 导出 placed/routed netlist、SDF、SPEF/GDS，再跑 STA 和物理验证。
阶段门禁
综合所有 cell/arc 可读，无 missing function/pin
放置site/row/orientation 合法，无 overlap，电源对齐
布线100% routed，pin access 和 router DRC 达标
STA所有 endpoint/arc 有模型，约束与 corner 完整

16.11 回归指标与 golden policy

保存结构化 manifest，而不是只保存截图：

cell, commit, tech_version, netlist_hash, placement_hash
width, height, transistor_count, route_iterations
wirelength_by_layer, via_count, pin_access_count
drc_counts_by_rule, lvs_status, pex_status
input_cap, leakage_states, delay/power summary
lef/gds overlay status, abutment status, pnr status

阈值来自库规格与项目经验，不存在通用“wirelength 增加 5% 就失败”的规则。正确性指标零容忍，QoR 指标采用经批准的预算和人工 review。

16.12 最终验收标准

能力合格证据
读版图能对 INV/NAND/NOR/AOI 逐层标出器件、DGSB、网络和对应 SPICE
读算法能解释放置图、路由图、成本，并用源码证明实际算法
改 LibreCell有最小 patch、测试、回归数据和清晰的 API/能力边界
迁移工艺能力矩阵、coupon、架构、外部 DRC/LVS/PEX 和 P&R 证据完整
交付库全部视图一致、characterization/QA 完整、known limitations 可执行
达到这里，才算从“会运行生成器”变成“能维护标准单元生成流程”。真正的独立性来自可追踪事实、源码理解和外部验证闭环，而不是记住一组参数。
最终自评
  1. 换 PDK 时，你能在动代码前列出所有 blocker 吗？
  2. 一个 GDS DRC/LVS clean 后，你能说明离可用 Liberty/LEF 还缺哪些证据吗？
  3. 一个 P&R 失败时，你能区分 pin access、LEF abstract、placement、routing 和 foundry rule 问题吗？
