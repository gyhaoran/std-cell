26.1 问题不是模型名字不好看，而是器件会被认反

本教程 commit 的 lccommon/net_util.py 使用“模型名以 n 开头就是 NMOS，否则就是 PMOS”的判断。一个新工艺模型叫 CORE_NFET，原解析器会把它识别为 PMOS。工具未必立刻报错，却可能在布局阶段把它分到错误行。未知模型必须尽早失败，不能默默选择默认类型。

# 原始规则的核心
if s.lower().startswith('n'):
    return ChannelType.NMOS
return ChannelType.PMOS

26.2 把需求写成三个可测试的不变量

  1. 已明确支持的 NMOS/PMOS 名称仍正确，不改变端口和 W 单位。
  2. 允许调用方提供“模型名→ChannelType”映射，大小写统一归一化。
  3. 未知模型或无效映射值抛出明确异常，停止生成；不把失败伪装成 PMOS。

练习选择 load_transistor_netlist(..., model_channel_types=None) 作为最小接口。未传 mapping 时只接受明确的 nmos/pmos，意味着以前依赖前缀猜测的其他名字现在会报错；这是有意收紧兼容性。真实发布需先盘点所有现有模型，提供迁移说明，不能以“原 INV 测试通过”宣称完全兼容。

26.4 一个必须单独解决的陷阱：SPICE 的 L 没有进入布局对象

原解析器从 KLayout 取 d.parameter('W')*1e-6，得到以米表示的 channel_width；创建的 Transistor 不保存 L。几何绘制在 layout/transistor.py 使用技术文件的 gate_length 画栅。因此，只把 CDL 的 L 改成两倍，不保证输出栅长跟着变。

这不是“SPICE 没有 L”，而是 LibreCell 这一实现丢弃了这个参数。若工艺只允许一种栅长，至少增加网表 L 与 tech.gate_length 一致性检查；若要支持多种 L，则需扩展数据结构、布局间距、绘图、提取比较和输出验证。不能在本文小补丁中偷偷把所有任务一起改掉。

26.5 从解析实验进入产品代码，还差哪些连接

  1. 在 tech API 中声明 model mapping 的格式与默认行为。
  2. 让 standalone._01_load_netlist 把该映射传入解析器；本练习尚未修改这个调用链。
  3. 保留器件模型族、Vt、body 与 L 等必要元数据，确定哪些下游模块必须消费。
  4. 用 INV/NAND/NOR，再用多个模型族和宽器件，跑布局、内部 LVS 与外部 LVS。
  5. 检查未知模型的失败发生在输出发布之前，并把错误写进每单元日志。
本章验证的是解析函数的真实补丁，不是“新工艺已经迁移完成”。完整 lclayout 仍受当前环境缺少 z3/pysmt 的限制；没有伪造整条流水线的成功日志。
练习

给目标工艺的 NMOS/PMOS 各写一个模型映射与反例；说明将 mapping 接入 tech API 后，哪些旧调用方可能受影响。

核对要点

映射键用确切模型名，值用内部 ChannelType；必须覆盖大小写、未知名称、错误值、多器件混合。调用链至少包括独立解析脚本、主生成入口和测试，不能只让当前测试传入 mapping 而产品入口仍用默认值。
