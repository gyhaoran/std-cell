第 8 章　DRC、LVS 与 PEX 实验

几何合法、连接一致、寄生可用是三个不同问题

本章目标
  • 区分 DRC、ERC、LVS 与 PEX 的输入、输出和能证明的事情。
  • 会在 KLayout 中逐层查看 GDS，并运行一个语法真实的教学 DRC。
  • 会按错误类别调试，而不是一看到 LVS fail 就盲目改版图。

8.1 四种验证各自回答什么

检查比较/分析对象能发现不能单独证明
DRC版图几何 vs 设计规则宽度、间距、包围、面积、密度等违规逻辑连接正确、时序正确
ERC提取网络的电气约束悬空井、非法电源连接、栅过压等全部制造规则和功能
LVS版图提取网表 vs 参考 SPICE/CDL开路、短路、缺失/多余器件、参数或端口不匹配寄生后性能、引脚可接入性、完整 DRC
PEX从已验证版图提取寄生参数互连 R/C、耦合和器件寄生模型本身的精度和全部系统性能

8.2 用 KLayout 建立逐层观察习惯

打开一个 GDS 后先选对 top cell，再做以下动作：

  1. 只显示 well/implant/active，确认器件区域。
  2. 加入 Poly，数 Active×Poly 交叠。
  3. 加入 contact 和 M1，追局部网络。
  4. 加入通孔/M2/引脚，确认引脚可接入性与电源轨。
  5. 用 ruler 量测时同时确认显示单位和 GDS DBU。

命令行打开：

klayout path/to/cell.gds

KLayout 的 layer list 可以隐藏/显示层、配置颜色和层次深度。颜色仍只用于显示，网络判断必须依赖层定义与连通性。

8.3 一个可运行的教学 DRC

examples/dummy_tech_checks.drc 对齐 LibreCell 的 examples/dummy_tech.py 输出层和其中的少量基础规则。脚本核心语法如下：

source($input)
report("LibreCell dummy-tech teaching checks", $report)

active = input(1, 0) | input(1, 7)
poly   = input(3, 0)
metal1 = input(6, 0)
gate   = active & poly

gate.width(50.nm).output("gate.width", "Gate width violation")
metal1.space(50.nm).output("m1.space", "M1 spacing violation")

批处理运行：

klayout -b \
  -r examples/dummy_tech_checks.drc \
  -rd input=path/to/cell.gds \
  -rd report=path/to/cell.lyrdb
这个脚本不是签核 deck。层号和数值来自 LibreCell dummy technology，只用于学习 KLayout DRC 的 input、布尔层、width、space 与报告输出。迁移任何真实 PDK 时必须使用该 PDK 的授权 deck 和规定版本。

KLayout DRC 是基于 Ruby 的 DSL。浮点尺寸默认按微米处理，也可以明确写 300.nm；整数参数按 database unit 解释。初学时优先写单位，避免把 100 误认为 100 nm。

不依赖 LibreCell 环境的 DRC 自测

仓库还提供一个只依赖 KLayout 的故意违规 GDS 生成脚本：

klayout -b -r examples/make_drc_fixture.rb \
  -rd output=/tmp/dummy-drc-fixture.gds

klayout -b -r examples/dummy_tech_checks.drc \
  -rd input=/tmp/dummy-drc-fixture.gds \
  -rd report=/tmp/dummy-drc-fixture.lyrdb

打开报告应看到栅、多晶硅、M1、通孔的宽度或间距违规标记。这个实验同时验证脚本语法、单位和报告浏览流程。

8.4 如何读 DRC 报告

  1. 记录 tool、deck、PDK 和 layout commit/version。
  2. 先按 rule ID/category 聚类，不要按 marker 一个个随机修。
  3. 确认 marker 所在 cell 和层次；区分单元内部、边界和拼接违规。
  4. 回到 DRM 阅读适用条件，判断生成器参数错误、布线选择错误还是缺少后处理能力。
  5. 修复后全量重跑，防止一个补丁引入另一类 spacing/area 违规。

8.5 LVS 的实际流程

参考 SPICE/CDL ── normalize names/parameters ─┐
                                             ├─ graph/device comparison ─ report
GDS ── layer derivation ─ device extraction ─┘

调试 LVS 时按下面顺序最省时间：

  1. 端口：cell 名、pin 名、大小写、顺序、电源名是否一致？
  2. 器件数与类型：是否少提/多提 MOS，NMOS/PMOS/阈值类型是否正确？
  3. 开短路：接触孔/通孔是否缺失，两个网络是否意外合并？
  4. body：well/substrate/tap 是否接到正确电源？
  5. 参数：W/L、finger、并联串联归并和容差是否一致？
本地内部 LVS 的边界：lclayout/lvs/lvs.py 明确丢弃第 4 个 body 端子，并且提取能力只覆盖有限金属层，源码中还有“more than 2 metal layers”的 TODO。它能帮助捕捉早期连接错误，但新工艺验收必须以外部 PDK LVS/ERC 为准。

8.6 PEX 为什么必须在 LVS 之后

PEX 在版图网络上添加寄生。如果网络本来就短路或开路，提取出的精细 R/C 也没有意义。典型顺序是：

DRC 通过 → LVS 匹配 → PEX → 版图后 SPICE 仿真 → 特征化

对标准单元，需关注输出扩散与互连电容、输入栅/布线电容、内部节点电容、金属/扩散电阻和耦合。特征化工具应采用与目标 PVT 条件（corner）对应的器件模型和 PEX 技术文件。

8.7 单元通过还不够：必须做拼接检查

标准单元会在 row 中以 R0、MX 等方向紧密相邻。单个 cell DRC clean 不代表两个 cell 边界组合 clean。最少应生成：

  • 每种 cell 与自己、与最窄/最宽 cell 的左右拼接；
  • 允许方向的 R0/R0、R0/MX、MX/R0、MX/MX；
  • 普通逻辑与 filler/tap/endcap 的组合；
  • 上下 row 共享电源轨和 well 的组合。
故意制造错误的学习法

在一个副本中分别制造三种错误：缩窄 M1、删除 Via1、把输出金属碰到 VDD。预测哪一种由 DRC 发现，哪一种主要由 LVS 发现，再运行验证核对。不要修改唯一的黄金版图。

本章检查点
  1. 删除一个通孔，为什么 DRC 可能仍然无违规？
  2. 为什么不能用 LibreCell 内部 LVS 的 pass 代替 foundry LVS？
  3. 为什么单元拼接矩阵属于库签核，而不是可选美化？
参考答案

删除通孔可能没有留下任何非法几何，却造成开路，需 LVS 发现。内部 LVS 忽略体端且层/器件提取有限。真实芯片中单元必然相邻和镜像，边界层组合可能产生单个单元中不存在的间距、凹槽或井规则违规。

工具依据：KLayout 基础手册与官方 DRC 基础文档。Calibre 手册只用于理解工业验证分层，本教程的可执行入门实验采用 KLayout。
